### How Agile works in my project

We follow an **Agile-based process with PI planning and 15-day Sprints**.

| Level | Our Process |
| --- | --- |
| **PI** | ~3 months, consisting of **6 Sprints** |
| **Sprint** | 15 days |
| **Command** | Major functionality planned for the PI |
| **Feature** | Command is divided into features |
| **User Story** | Each feature is broken into multiple user stories |
| **Acceptance Criteria** | Defines expected behavior/conditions of the user story |
| **Test Cases** | QA creates test cases based on User Stories & Acceptance Criteria |
| **Test Run** | QA executes test cases and tracks Pass/Fail |

### Example

**PI → Datum Feature Symbol (DFS) Command**

→ Features: **Create DFS, Edit DFS, Leader Preview, etc.**

→ Each Feature has multiple **User Stories**

→ User Stories contain **Acceptance Criteria**

→ QA creates **Test Cases**

→ Test Cases are executed through **Test Runs**

* * * * *

Sprint Flow in Our Project
--------------------------

-   **Sprint 1--4:** Mainly feature development and testing.
-   **Sprint 5:** Mostly command-level testing.
-   **Sprint 6:** Mainly **Regression + Pre-production testing**.
-   After successful validation → **PI delivery/release**.

> This timeline is our team's process; it is not a mandatory Scrum rule.

* * * * *

Scrum Ceremonies
----------------

| Ceremony | Purpose / QA Role |
| --- | --- |
| **Sprint Planning** | Decide Sprint work; QA understands stories, requirements, testing effort and risks. |
| **Daily Stand-up** | Share yesterday's work, today's plan and blockers. |
| **Backlog Refinement** | Discuss upcoming stories; QA clarifies requirements and identifies test scenarios. |
| **Sprint Retrospective** | Discuss what went well, problems and improvements. **Our team does it mostly after 3 Sprints.** |
| **Sprint Review** | Demonstrate completed work and collect feedback. |

* * * * *

⭐ What does QA do during a Sprint?
----------------------------------

> **Understand User Stories → Clarify requirements → Create test cases/data → Execute testing → Report defects → Retest → Regression → Update status → Communicate progress/blockers.**

### 🔥 Interview answer: "How does Agile work in your project?"

> **In our project, we work in a PI-based Agile model. One PI is around three months and contains six 15-day Sprints. At the beginning of the PI, we plan a major command or functionality and divide it into multiple Features. Each Feature is further divided into User Stories with Acceptance Criteria. As QA, I create test cases based on these requirements, execute them when the features are available, report and retest defects, and perform regression and pre-production testing in the later Sprints. We also participate in Sprint Planning, Daily Stand-ups, Backlog Refinement, Sprint Reviews and Retrospectives.**
