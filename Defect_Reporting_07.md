Defect Reporting ⭐⭐⭐⭐⭐
======================

A **good defect report should help the developer understand, reproduce, and fix the issue quickly**.

Defect Report Format
--------------------

| Field | What to Include |
| --- | --- |
| **Bug ID** | Unique defect ID, e.g. `BUG_001` (usually auto-generated by Jira/tools) |
| **Bug Title / Summary** | Short and clear description of the issue |
| **Environment** | QA/Staging, application version/build, browser, OS, etc. |
| **Preconditions** | Required conditions before reproducing the issue |
| **Steps to Reproduce** | Clear step-by-step actions to reproduce the issue |
| **Expected Result** | What should happen according to the requirement |
| **Actual Result** | What actually happened |
| **Severity** | Impact of the defect on the application |
| **Priority** | Urgency of fixing the defect |
| **Reproducibility** | Always / Sometimes / Rarely |
| **Attachments** | Screenshots, videos, logs, etc. |
| **Comments** | Additional information or observations |
